#### Address formats for manual entry

When variables are entered manually via the UI or imported via CSV, the following address formats apply.

**Absolute addressing**

Structure: `DB<Nr>.DB<B|W|D|X><ByteOffset>.<BitOffset>`

<ul>
  <li>The operand type (DBB, DBD, DBX, DBW) can be used interchangeably — it is for readability only</li>
  <li>The bit offset is optional and may be omitted together with the separating period</li>
  <li>Spaces must be removed</li>
</ul>

Examples: `DB9.DBX200.2` (bit 2 of byte 200 in DB 9), `DB30.DBW558` (byte 558 in DB 30)

**Symbolic addressing**

Structure: `PLC.Blocks.<DataBlock>.<Variable>`, always starting with `PLC.Blocks.`

<ul>
  <li>Names containing a period must be enclosed in double quotes: <code>"My.Name"</code></li>
  <li>A double quote inside a name is escaped by doubling it: <code>"My""Name"</code></li>
  <li>Case-sensitive</li>
</ul>

Examples: `PLC.Blocks.TestDB.MyVariable`, `PLC.Blocks.TestDB."My.Structure".MyVariable`, `PLC.Blocks.TestDB.Array.Element[28]`

:::note
Invalid addresses — common with manual entry — silently prevent data access. Using the import function avoids this: variables are correctly formatted and escaped automatically.
:::

| Property | Value |
| --- | --- |
| Protocol | OPC UA |
| Default port | 4840 (configurable in PLC project) |
| Authentication | Anonymous or username / password |
