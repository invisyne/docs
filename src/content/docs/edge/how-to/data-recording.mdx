Data recording is the mechanism by which the Edge connects to field devices, reads configured process variables at a defined sampling interval, and stores the measured values in its internal time-series database. These stored values serve as the data source for Grafana dashboards and can optionally be forwarded to external platforms such as AWS IoT Core.

Before variables can be configured, the field device must already be added to the Edge and a connection must be established. The following information should be available:

- **IP address** of the field device
- **Device type** (Modbus TCP, OPC UA, or Siemens SIMATIC S7)
- **Variable addresses or structure**: for manual entry or CSV-based import, the addresses of the variables to be recorded (see [Protocols and Field Devices](/edge/technical-reference/protocols) for address formats); for S7 controllers with symbolic addressing, a live connection to the PLC is sufficient — the built-in import browser retrieves the variable structure directly from the device.

See [Adding a Field Device](/edge/how-to/add-field-device) for step-by-step instructions on adding and connecting the device before proceeding.

    </div>

**CSV file structure**

The CSV file uses **semicolon (`;`)** as the delimiter and must be UTF-8 encoded. The first row contains the column headers — spelling and spacing must match exactly.

```
Messgroessenname;Aktiv;Abtastrate (ms);Datentyp (SPS);Datentyp (Crawler);Gruppe;Adresse;Tags
```

<div class="def-list">
  <span class="def-list-key">Messgroessenname</span><span class="def-list-val">Variable name — must be unique within its group level</span>
  <span class="def-list-key">Aktiv</span><span class="def-list-val"><code>true</code> or <code>false</code> — whether recording starts immediately after import</span>
  <span class="def-list-key">Abtastrate (ms)</span><span class="def-list-val">Sampling interval in milliseconds, e.g. <code>1000</code></span>
  <span class="def-list-key">Datentyp (SPS)</span><span class="def-list-val">PLC-side data type of the variable, e.g. <code>S7_Real</code>, <code>S7_Bool</code>, <code>S7_Int</code>, <code>FLOAT</code>, <code>BOOLEAN</code></span>
  <span class="def-list-key">Datentyp (Crawler)</span><span class="def-list-val">Edge-side data type — typically <code>FLOAT</code> for numeric values or <code>STRING</code> for text and time values</span>
  <span class="def-list-key">Gruppe</span><span class="def-list-val">Group name for organizing variables in the Variable Browser, e.g. <code>Motor1</code> or <code>PAC0</code></span>
  <span class="def-list-key">Adresse</span><span class="def-list-val">Variable address in the device-specific format (see address formats below)</span>
  <span class="def-list-key">Tags</span><span class="def-list-val">Optional tags, comma-separated — can be left empty</span>
</div>

**Manually creating a variable**

:::note
Before variables can be created manually, the device must have at least one **root group** (top-level group). Without a root group, the **+ Add variable** button is not available. A group can be created via **+ Add group** directly in the Variable Browser.
:::

Variables can also be created without an import. Click **+ Add variable** in the Variable Browser to open the creation dialog. Enter the variable name, address, data type, and sampling interval.

**Editing or deleting a single variable**

The following settings can be changed for a measured variable:

<div class="def-list">
  <span class="def-list-key">Name</span><span class="def-list-val">Name changes require adjustments in existing dashboards; the name should be unique within its group level</span>
  <span class="def-list-key">Sampling rate</span><span class="def-list-val">Range: 10 ms to 500 h, specified in milliseconds</span>
  <span class="def-list-key">Recording</span><span class="def-list-val">Start and stop recording</span>
  <span class="def-list-key">Timestamp alignment</span><span class="def-list-val">When enabled, the timestamp of each recorded value is snapped to the nearest multiple of the sampling interval, aligning samples from different variables to a common time grid. This makes side-by-side comparison of variables in Grafana more accurate.</span>
  <span class="def-list-key">Recording metrics</span><span class="def-list-val">When enabled, internal performance counters are stored alongside the measured value — for example, actual vs. expected sample counts per interval. Useful for diagnosing timing issues or evaluating recording quality.</span>
  <span class="def-list-key">Tags</span><span class="def-list-val">Add/remove</span>
</div>

**Bulk editing or deleting**

To edit or delete multiple variables at once, select them in the Variable Browser by adding them to the cart. Selected variables are highlighted in color; the number of selected items is shown on the cart icon. Open the cart to review and adjust the selection. Removing a variable from the cart does not delete it.

The Performance Analysis tool tests whether the Edge is sampling variables at the configured rate. It checks that no values are missed or delayed — useful after setup or when adjusting sampling intervals.

:::note
Recording for the tested device is interrupted while a test is running. Do not run performance tests on a device that is actively recording production data.
:::

Open the device page and click **Performance Analysis** to open the analysis overview. The last test result is shown alongside the available test types.

<div class="screenshot-frame">
  <img src={perfOverviewImg.src} alt="Performance Analysis overview — test selection and last results" />
</div>

Click **Run test** under **Setpoint-Actual Comparison** to open the configuration dialog. Select a test duration using the slider (10 seconds to 30 minutes) and click **Start**.

<div class="screenshot-frame screenshot-frame-sm">
  <img src={perfStartImg.src} alt="Setpoint-Actual Comparison start dialog with duration slider" />
</div>

A warning is shown before the test starts confirming that recording will be interrupted.

<div class="screenshot-frame screenshot-frame-sm">
  <img src={perfWarningImg.src} alt="Warning: recording will be interrupted during the test" />
</div>

The test runs in the background and shows a progress indicator. Do not switch off the Edge or the data source while the test is running.

<div class="screenshot-frame">
  <img src={perfRunningImg.src} alt="Performance Analysis — test running with progress indicator" />
</div>

After completion, the results page shows a quality rating (color scale from red to green), the number of failed test runs, and key statistics including average, median, minimum, and maximum sampling rate.

<div class="screenshot-frame">
  <img src={perfResultsImg.src} alt="Performance Analysis results — quality rating and sampling rate statistics" />
</div>

If the quality rating is **poor** (red or orange), the most common causes are a sampling interval that is too short relative to the network round-trip time to the field device, or a high number of simultaneously recorded variables exceeding the available bandwidth. In these cases, consider increasing the sampling interval, reducing the number of actively recorded variables on the device, or running the test on individual variables to isolate the bottleneck. Contact support if the issue persists after adjusting the configuration.
