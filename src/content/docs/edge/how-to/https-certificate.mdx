From Edge 2.22, the web interface is accessible via HTTPS only. By default, the device uses a self-signed certificate — browsers display a security warning on first access. This happens because the browser cannot verify the certificate through a public authority, not because anything is wrong with the device or the connection.

**The connection is always encrypted, even when the warning is shown.** The warning simply means the browser cannot automatically confirm the device's identity.

There are three ways to handle this:

1. **Upload a custom certificate** (IT-issued) — permanently removes the warning.
2. **Trust the device certificate in the browser** — import once into the Windows certificate store; covers Chrome, Edge, and Firefox.
3. **Click through the warning** — no setup required; the connection remains encrypted.

:::tip
If your organization does not have an internal certificate authority, option 2 (trust in browser) is the recommended approach.
If neither option is feasible, HTTP-only mode is available as a fallback — see [Switch to HTTP-only Mode](/edge/how-to/http-mode).
:::

## Option 1: Upload a Custom Certificate (IT-issued)

Your IT department must issue a valid TLS certificate for the IP address or hostname under which the Edge device is accessed on your network.

| File | Required |
|------|----------|
| Certificate bundle (`.crt`, `.pem`, or `.cer`) | Yes |
| Private key file | No |
| Key passphrase | No (only if the key is passphrase-protected) |

### Via Network Settings

<Steps>
1. Open the Edge web interface and log in.

2. Go to **Settings** → **Network**.

3. Scroll to the **Certificate** section.

4. Click **Upload Certificate**, select the bundle file, and optionally attach the key file and enter the passphrase.

5. Click **Save**. The certificate is applied immediately — no restart required.
</Steps>

### Via Setup Wizard (during initial setup)

<Steps>
1. Start the Setup Wizard for the Edge device.

2. In the **Network** step, scroll to the **Certificate** section.

3. Upload the certificate bundle and optionally the key file and passphrase.

4. Continue and complete the wizard.
</Steps>

## Option 2: Trust the Device Certificate in the Browser

Chrome, Edge, and Firefox on Windows all use the Windows certificate store. Importing the device certificate once removes the warning in all three browsers.

:::caution
**When to repeat this:** If the Edge device's IP address changes, its certificate is automatically regenerated. The old trust no longer applies — repeat the import steps with the new certificate. The certificate is also regenerated after approximately 825 days (about 2.25 years).
:::

### Step 1 — Export the certificate from the browser

#### Chrome or Microsoft Edge

<Steps>
1. Navigate to `https://<device-ip>`. The browser shows a "Your connection isn't private" warning.

   <div class="screenshot-frame"><img src={warningPageEdge.src} alt="Browser warning page in Edge" /></div>

2. Click **Advanced**, then click **Continue to \<device-ip\> (unsafe)** to load the page.

   <div class="screenshot-frame"><img src={warningAdvancedEdge.src} alt="Advanced section with proceed link" /></div>

3. Once the page loads, click **Not secure** in the address bar.

   <div class="screenshot-frame"><img src={notSecureClick.src} alt="Not secure indicator in the address bar" /></div>

4. Click the certificate details link.

   <div class="screenshot-frame"><img src={clickCertDetailsEdge.src} alt="Certificate details link in the dropdown" /></div>

5. In the Certificate Viewer, switch to the **Details** tab and click **Export**. Save the file.

   <div class="screenshot-frame"><img src={certDetailsEdge.src} alt="Certificate Viewer — Details tab with Export button" /></div>
</Steps>

#### Firefox

<Steps>
1. Navigate to `https://<device-ip>`. Firefox shows a warning page.

   <div class="screenshot-frame"><img src={warningPageFirefox.src} alt="Browser warning page in Firefox" /></div>

2. Click **Advanced**, then click **View the site's certificate**.

   <div class="screenshot-frame"><img src={warningAdvancedFirefox.src} alt="Advanced section with certificate link" /></div>

3. Firefox opens a certificate details tab. Scroll to the **Miscellaneous** section and click **PEM (cert)** to download the file.

   <div class="screenshot-frame"><img src={certViewSaveFirefox.src} alt="Certificate details page with PEM download link" /></div>
</Steps>

### Step 2 — Import into the Windows certificate store

<Steps>
1. Press **Win + R**, type `certmgr.msc`, and press Enter.

   <div class="screenshot-frame"><img src={certmgrOpen.src} alt="Windows Certificate Manager" /></div>

2. In the left panel, expand **Trusted Root Certification Authorities** and select **Certificates**.

   <div class="screenshot-frame"><img src={certmgrTrustedRoot.src} alt="Trusted Root Certification Authorities store" /></div>

   :::note
   Self-signed certificates must be imported here (not into Personal or Intermediate). This is the only store browsers check for TLS trust decisions on self-signed certificates.
   :::

3. Right-click **Trusted Root Certification Authorities** → **All Tasks** → **Import**.

4. The Certificate Import Wizard opens. Click **Next**, browse to the certificate file, and select it.

   <div class="screenshot-frame"><img src={certmgrImportWizard.src} alt="Certificate Import Wizard" /></div>

5. Confirm the store is set to **Trusted Root Certification Authorities**, then click **Next** → **Finish**.

6. A security confirmation appears — click **Yes** to trust the certificate.

   <div class="screenshot-frame"><img src={certmgrImportWizardConfirm.src} alt="Security confirmation dialog" /></div>
</Steps>

:::note
Importing into the Windows certificate store requires local administrator access. If access is restricted, ask your IT department to perform the import.
:::

### Step 3 — Verify

Close **all** browser windows (browsers cache certificate decisions for the entire session — closing just the tab is not enough). Reopen the browser and navigate to `https://<device-ip>`. A padlock icon should appear with no warning.

<div class="screenshot-frame"><img src={edgeSecure.src} alt="Secure connection padlock in browser" /></div>

**If the warning still appears, check:**
- The IP address matches the IP in the certificate's SAN field
- The certificate is in **Trusted Root Certification Authorities**, not another store
- All browser windows were fully closed and reopened

**Firefox note:** Firefox reads the Windows certificate store via `security.enterprise_roots.enabled`, which is enabled by default since Firefox 68. If Firefox still shows a warning, navigate to `about:config`, search for `security.enterprise_roots.enabled`, and ensure it is set to `true`.

---

## Option 3: Click through the warning

No setup is required. Every browser provides an option to proceed despite the warning. The connection is encrypted regardless — only identity verification is skipped.

This is suitable for occasional access or when neither of the above options is practical.
