## Key Concepts

### Locales
- **English** (root locale): content at `src/content/docs/` — no `/en/` prefix in URLs
- **German**: content at `src/content/docs/de/` — URLs prefixed with `/de/`
- Locale config is in `astro.config.mjs` under `locales`

### Sidebar
Defined entirely in `astro.config.mjs`. Three top-level product groups (Edge, Companion, Hub).  
**Active product filtering**: only the product group containing the current page is visible — controlled by CSS in `custom.css`:
```css
.top-level > li:not(:has(a[aria-current='page'])) { display: none; }
```

For Hub How-To guides, the sidebar uses **explicit items** (not autogenerate), so individual guide titles appear directly without the index.mdx being listed.

### Tab Components (Quickstart & How-To)
All tab functionality runs via client-side JS in `Header.astro` (`initQsTabs()`).  
Each `.qs-stepper` div is **independently initialized** — multiple tab groups can coexist on one page.

**HTML pattern** (tabbar before panels = tabbar appears on top):
```html
<div class="qs-stepper">
  <div class="qs-tabbar">
    <a class="qs-tab" href="#">Tab 1</a>
    <a class="qs-tab" href="#">Tab 2</a>
  </div>
  <div class="qs-panels">
    <div class="qs-panel">...content 1...</div>
    <div class="qs-panel">...content 2...</div>
  </div>
</div>
```

CSS grid stacking (`grid-row: 1; grid-column: 1`) keeps all panels at the same height — no layout jump.

### Changelogs
**Never edit `changelog.md` files manually** — they are overwritten on every `npm run generate`.  
Source is the `../release-notes` repository (local) or a CI checkout path.  
Run `node scripts/generate-changelogs.js` to regenerate.

### Language Persistence
When navigating between Hub / Edge / Companion via the top product nav, the current language (DE/EN) is preserved automatically. This is handled in `Header.astro` via the `updateProductNavLinks()` function, which reads `window.location.pathname` and updates the nav `href` attributes dynamically.

## Where to Add New Features

| What you want to add | Where to change |
|---|---|
| New Hub how-to guide (EN) | Create `src/content/docs/hub/how-to/my-guide.md` + add to `astro.config.mjs` sidebar items |
| New Hub how-to guide (DE) | Create `src/content/docs/de/hub/how-to/my-guide.md` (same slug) |
| New Hub UI Reference page | Create `src/content/docs/hub/ui/my-page.md` — sidebar auto-discovers via `autogenerate` |
| New product section | Add a new item group in `astro.config.mjs` sidebar + create content folder |
| Global styles | `src/styles/custom.css` |
| Top navigation behaviour | `src/components/Header.astro` (CSS in `<style>`, JS in `<script>`) |
| Sidebar toggle button | `src/components/Sidebar.astro` |
| New component | Create `src/components/MyComponent.astro`, override in `astro.config.mjs` under `components:` |
| Language toggle appearance | `src/components/LanguageSelect.astro` |

## Content Conventions

- **Frontmatter**: always include `title` and `description`
- **Callouts**: use `:::note`, `:::tip`, `:::caution`, `:::danger` (not Archbee `:::hint`)
- **Step sequences**: use `<Steps>` from `@astrojs/starlight/components`
- **Images**: store in `src/assets/images/`, reference with relative paths
- **Filenames**: lowercase kebab-case
- **Product name**: write **Edge (Crawler)** in body text; sidebar/titles may use "Edge" alone
- **No HTML comments** in `.mdx` files (`<!-- -->` causes a parse error)
- **No `<script>` tags** in `.mdx` files (braces are parsed as JSX)

## Known Quirks

- **Sidebar filter CSS** uses `:has()` — not supported in Firefox < 121. Works in all modern browsers.
- **Sidebar toggle button** is appended to `document.body` (not inside `.sidebar`) to avoid `transform: translateX` stacking context issues.
- **Changelog files** are generated at `src/content/docs/{product}/changelog.md` and will be overwritten on next `npm run generate`. Treat them as build artifacts.
- **MDX files** cannot contain `<!-- HTML comments -->` or bare `<script>` tags. Use JS-based approaches in `Header.astro` instead.
